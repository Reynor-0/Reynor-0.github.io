# PHY88Q1110

最近在实习过程中接触到了PHY88Q1110这款芯片的开发，于是去英飞凌的官网上阅读了这款芯片的数据手册，简单记录一下学习与实习工程中的经验。

BRIGHTLANE 88Q1110 是一颗单端口 100BASE-T1 PHY，符合 IEEE 802.3bw 标准，工作速率为 100 Mbps。它的一侧连接 MCU、SoC 或以太网交换芯片中的 MAC，另一侧则通过 MDIP、MDIN 两个引脚连接单对平衡双绞线。

一个比较经典的硬件电路可以简化为以下的形式：

```
CPU / SoC / Ethernet Switch
            │
    RGMII / MII / RMII  
            |
        88Q1110   
            |
            MDI
            |
        单对车载双绞线
            |
        对端100BASE-T1 PHY
```

这里再简要区分一下MAC和PHY的职责。MAC处理的是以太网帧，例如目的MAC地址、CRC、帧间隔以及DMA描述符；PHY处理的是如何把这些数据可靠地发送到线缆上，以及如何从受到噪声、衰减、反射和阻抗不连续影响的模拟信号中恢复出数字数据。所以88Q1110本身不是交换机也不处理IP、TCP或者UDP报文。他需要链接一个具备以太网MAC的控制器或者交换芯片，才能组成一个比较完整的以太网端口。

***

## 88Q1110 和 88Q1111 的区别

数据手册同时介绍了88Q1110 和 88Q1111。两者的 100BASE-T1 线缆侧功能基本一致，主要差异集中在 MAC 侧接口。

|型号       |   MAC 侧接口      |	更适合的连接对象|
| ---       | ---               | ---              |
|88Q1110    |	RGMII、MII、RMII|	MCU、SoC 或带并行 MAC 接口的交换芯片|
|88Q1111    |	SGMII           |	带 SERDES 或 SGMII 端口的交换芯片、SoC|

88Q1110 可以在 RGMII、MII 和 RMII 之间选择。88Q1111 则使用 SGMII，通过一对差分线以 1.25 Gbps 的串行速率传输编码后的数据，从而减少 MAC 侧使用的引脚数量。需要注意的是，SGMII 接口的串行线速率虽然是 1.25 Gbps，但它连接的铜缆侧仍然是 100 Mbps 的 100BASE-T1。有关MII这些概念，先前在xxx介绍过，可以参考一下。

这里再简要说一下什么是100BASE-T1

100BASE-T1 是一种面向车载和工业场景的单对线以太网标准，其中： 
- `100` 表示传输速率为 100 Mbit/s； 
- `BASE` 表示使用基带传输； 
- `T1` 表示使用一对双绞线进行通信。

那么1000BASE-T1就是传输速率提高到了1Gbit/s的标准。

## PHY 地址和 Strap 配置

88Q1110 支持通过硬件 Strap 引脚确定启动配置。在复位释放时，芯片会采样部分复用引脚上的电平，用于决定以下的内容：
- PHY地址
- Master或者Slave模式
- RGMII、MII或者RMII接口模式
- TC10默认配置

Strap配置怎么理解呢，用过linux板子或者玩过电脑主板的同学可能比较熟悉，可以通过拨码开关、跳线等，来提前设置某些功能。硬件工程师通过在某些引脚上链接上拉或者下拉电阻，提前告诉芯片：

- 我的 PHY 地址是多少；
- 我要工作在 Master 还是 Slave；
- MAC 侧使用 RGMII、MII 还是 RMII；
- 是否默认启用 TC10

这些信息需要在软件驱动运行之前就确定，因此不能完全依赖之后写入寄存器的操作。
88Q1110 会在 RESETn 解除，也就是由低变高之后，读取 GPIO、RXD、RXC、RCLK 等引脚的状态，并将结果锁存为启动配置。完成采样后，这些引脚再恢复成 RXD、时钟或 GPIO 等正常功能。下一次硬件复位时，芯片会重新采样。

## MDIO 管理接口

驱动程序通过MDC和MDIO访问88Q1110的寄存器。其中：
- MDC是管理接口时钟
- MDIO是双向管理数据线

这里的思想和CAMERA的思想有点像，都是配置走一个总线，具体数据走另一个总线。他们也都属于数据流量比较大的场景。

88Q1110支持Clause 45管理接口，还有Clause 22。这里也做一个简要的介绍。
Clause 22 和 Clause 45是 IEEE 802.3 中关于 MDIO 管理接口的两种寄存器访问方式。他们用的硬件引脚相同，都是MDC和MDIO。二者最大的区别就是如何去描述一个PHT内部的寄存器地址，可以这样简单的理解：

```
Clause 22：PHY 地址 + 5 位寄存器地址

Clause 45：PHY 地址 + MMD 设备地址 + 16 位寄存器地址
```
这里不代表Clause 22就无法完成MMD(Clause 45 扩展寄存器空间）)的设备地址和寄存器地址，可以通过IEEE 802.3 标准的 Clause 22 间接访问机制来完成。这也是我实习过程中的方式。

IEEE 802.3 定义了两个标准寄存器：
- Register 13 (0x0D) = MMD Access Control：bit14 是 Function（0=地址模式，1=数据模式），低 5 位是 DEVAD
- Register 14 (0x0E) = MMD Address/Data

以读操作为例：
```c
phy88q1110_write_reg(dev, phyaddr, 13, devaddr,              SMI_CLAUSE_22);  // ① 写 DEVAD 到 reg13，function=0 → 寄存器14进入"地址"模式
phy88q1110_write_reg(dev, phyaddr, 14, regaddr,             SMI_CLAUSE_22);  // ② 把 MMD 寄存器地址写入 reg14
phy88q1110_write_reg(dev, phyaddr, 13, (0x01<<14)|devaddr,  SMI_CLAUSE_22);  // ③ 重新写 reg13，bit14=1 → 寄存器14切换为"数据"模式
val = phy88q1110_read_reg (dev, phyaddr, 14,                SMI_CLAUSE_22);  // ④ 读 reg14 拿到该 MMD 寄存器的数据
```
也就是每 4 次 Clause 22 总线事务才能完成一次 MMD 访问（读：3 写 + 1 读；写：3 写 + 1 写），这就是间接访问的代价。这样就不依赖MAC 控制器是否支持原生 Clause 45。

## 初始化流程

88Q1110的初始化流程通常包括

```text
释放PHY复位
等待PHY完成内部初始化
通过MDIO读取PHY ID
确认当前的PHY地址
配置Master/Slave模式
配置RGMII时钟延迟
配置中断
配置TC10
启动链路
link up link training
读取链路速率和状态
```

## Master和Slave

100BASE-T1 链路需要确定 Master 和 Slave。
这里的 Master 和 Slave 主要用于物理层时钟关系，并不表示业务协议中的主节点和从节点。例如，一颗 ECU 即使在应用层是服务端，也不一定必须配置成 PHY Master。

在嵌入式驱动中，可以在初始化阶段读取主从状态寄存器，用于确认： 
- 当前配置是 Master 还是 Slave； 
- 配置是否已经生效； 
- 是否发生主从配置冲突； 
- 链路训练是否失败。

## TC10 低功耗休眠与唤醒

88Q1110 支持 OPEN Alliance TC10 Sleep/Wake。
TC10 是车载以太网中非常重要的低功耗机制。它允许 PHY 和链路伙伴协商进入休眠，并支持通过本地信号或线缆侧信号唤醒。
普通 PHY Power Down 更接近软件关闭 PHY。进入这种状态后，通常只能通过 MDIO 操作重新唤醒。

TC10 不同。它需要考虑整个以太网节点的电源管理，包括：

- PHY； 
- MAC； 
- 以太网交换机； 
- PMIC； 
- MCU； 
- 外部唤醒信号； 
- 远端 PHY； 
- 整车网络管理。

88Q1110 可以通过以下方式被唤醒： 
- WAKE_IN 引脚产生本地唤醒； 
- 对端 PHY 通过线缆发送唤醒脉冲； 
- MAC 或交换机提出唤醒请求； 
- 软件通过寄存器触发唤醒。


芯片的 INH 引脚还可以参与外部电源控制。一个简化的休眠流程可以表示为：

```text 
上层网络管理请求休眠 
    │ 
停止发送新的业务数据 
    │ 
等待 MAC 数据发送完成 
    │ 
PHY 与对端进行 TC10 休眠握手 
    │ 
PHY 进入低功耗状态 
    │ 
INH 控制外部电源关闭 
```

唤醒流程则可能是：
```text 
WAKE_IN 或线缆侧检测到唤醒 
    │ 
PHY 退出低功耗状态 
    │ 
INH 请求恢复外部电源 
    │ 
MCU / Switch 启动 
    │ 
重新初始化 MAC 和 PHY 
    │ 
等待链路重新建立 
```

## 中断处理
中断事件可能包括： 
- Link Up； 
- Link Down； 
- 唤醒事件； 
- TC10 状态变化； 
- PTP 时间戳事件； 
- 诊断完成； 
- 错误状态。 

典型的中断处理流程为： 
```text 
PHY 拉低中断引脚 
    │ 
MCU 进入 GPIO 中断 
    │ 
中断服务程序唤醒工作线程 
    │ 
工作线程通过 MDIO 读取中断状态 
    │ 
清除中断标志 
    │ 
更新链路或电源管理状态 
```

## 驱动编写

### 软件架构

本次任务的编写主要分四个层次的编写逻辑：
- **MDIO 总线层** 只产生原生的Clause 22事务，用于读写指定的寄存器的，单次的Clause 22事务，经过dev->bus.bus_ops->read/write 进行读写；
- **MMD 寄存器层** 把Clause 45风格的 `(port, devad, regaddr)` 折叠成对 reg13/reg14 的 4 次顺序 Clause 22 访问；
- **业务逻辑层** 面向"上电序列 / TC10 初始化 / 进入 TPS / 进入 LPSD / 唤醒握手 / 链路状态读取"等语义级动作。提供以下的函数
```c
phy88q1110_power_sequence(...);
phy88q1110_tc10_init(...);
phy88q1110_set_phy_mode(...);
phy88q1110_enter_lpsd(...);
phy88q1110_wakeup_sequence_step1(...);
phy88q1110_wakeup_sequence_step2(...);
phy88q1110_link_is_up(...);
phy_check_wakeup_source(...);
```
- **控制接口层** 通过 `phy88q1110_control(dev, cmd, data)` 一个总入口分发大量 `ETH_DEV_*` 命令，是上层（switch manager / ethernet device manager）查询状态、触发动作、dump 寄存器的统一通道。

### 状态机设计


驱动用 `phy_dev->dev.consumption_mode` 维护一个二元状态：

```
              init / wakeup success
   ┌──────────────────────────┐
   │                          ▼
 ETHERNET_DEV_ACTIVE      ETHERNET_DEV_SLEEP
   │   ▲                          │
   │   │ wakeup ok                 │ set_sleep ok
   │   └──────────────────────────┘
   │
   └─ event_cb(ETHDEV_SLEEP_EVENT / *_WAKEUP_*)
```

- 进入 `SLEEP`：`phy88q1110_set_sleep` 成功后置位，`dev_ready=false`，并通过 `event_cb` 上报 `ETHDEV_SLEEP_EVENT`。
- 进入 `ACTIVE`：`phy88q1110_set_wakeup` 成功后置位，并通过 `event_cb` 上报 `ETHDEV_LOCAL_WAKEUP_EVENT_FROM_DEEP_SLEEP` 或 `ETHDEV_REMOTE_WAKEUP_EVENT_FROM_DEEP_SLEEP`。

### 初始化

**总线注册**

```c
mdio_register(&(dev->bus));
dev->bus.bus_ops->init(&(dev->bus));
```
注册并初始化 MDIO 总线驱动，这一步把 `dev->bus.bus_ops` 填好，后续 `phy88q1110_read_reg/write_reg` 才能用。

**上电时序 phy88q1110_poweron**

```
power_enable = 1     ──►  sleep 1ms
(LPSD) if INH=high:                  // PHY 处于深度睡眠
        WAKE_IN 拉高  ──►  sleep 1ms  ──►  WAKE_IN 拉低  ──►  sleep 1ms
RESET 拉到复位电平  ──►  sleep 2ms
RESET 释放到正常电平 ──►  sleep 5ms
```

**INH 仍为睡眠电平时的强制唤醒**


如果 `poweron` 之后 INH 仍为高（说明 PHY 没被 WAKE_IN 脉冲唤醒），驱动会做一次"再入睡再唤醒"的兜底：

```c
phy88q1110_enter_lpsd(dev);          // 让 PHY 重新进入一个已知 LPSD 状态
sleep 1ms;
WAKE_IN 拉高 1ms → 拉低 1ms;          // 再发一次唤醒脉冲
```

如果 INH 还是高，记录 ERROR 日志但继续往下走（上电序列本身会做最后兜底）。

**上电序列 phy88q1110_power_sequence**

```
(LPSD) phy88q1110_wakeup_sequence_step2(net_dev):
        sleep 1ms → 等待 power=low → set_power(1) → sleep 1ms
        → WAKE_IN 拉低 → sleep 1ms → RESET 释放 → sleep 5ms
loop retry < 5:
    phy_id = phy88q1110_read_phy_reg(net_dev, 0, 0x01, 0x0002, false)
    if phy_id == 0x002B: break
    else: retry++
if retry 满 5 次都拿不到正确 PHY ID → 上层会看到 E_NOT_OK，但本函数仍继续
phy88q1110_write_phy_reg(net_dev, 0, 0x04, 0x8703, 0xffff, false)   // 写 1 清 TC10 状态
phy88q1110_tc10_init(dev)
```

- **PHY ID 校验**期望 `0x002B`，这是 88Q1110 的标识。读不到通常意味着 MDIO 没通或 PHY 没醒。
- **写 0x8703 = 0xFFFF** 是写 1 清零（W1C）状态寄存器的标准操作。

**TC10 初始化 phy88q1110_tc10_init**

这里涉及到公司内的一些特殊配置，不予展示，这里知道是往寄存器写一些值来控制TC10的表现就行了

**主从模式初始化**

```c
val = read_phy_reg(MMD1, 0x0834)
if (is_init_port_master)  val |= 0x4000;   // bit14=1 → master
else                      val &= ~0x4000;  // bit14=0 → slave
if (val != init_val) {
    write_phy_reg(MMD1, 0x0834, val);
    write_phy_reg(MMD1, 0x0000, 0x8000);   // Soft Reset / 应用新配置
}
```

100BASE-T1 是点对点链路，必须一端 master 一端 slave。至此初始化结束。

### 状态查询与控制

所有运行时交互都走 `phy88q1110_control(dev, cmd, data)` 。可以举出一两个例子。

- ETH_DEV_GET_LOWEST_SQI 用于查询最低的SQI等级，可以理解为整个线路的信号质量；
- ETH_DEV_GET_PORT_STATUS 查询相关寄存器的结果
- ETH_DEV_POWER_SEQ_CMD 是唤醒后必经的命令，它：
1. 调 `phy88q1110_power_sequence` 完成 ID 校验 + TC10 init；
2. （LPSD）循环最多 `PHY_MDIO_OP_MAX_RETRY_TIMES (10)` 次调 `phy_check_wakeup_source`，每次 sleep 5ms；
3. 没拿到结果就置 `*data = ETHDEV_UNKNOWN_EVENT`，否则填 `LOCAL` 或 `REMOTE`；
4. 再读一次 `0x8703` 打印 `sleep_status` 日志。
多余的不予介绍。

### 休眠

phy88q1110_sleep(dev,mode) -> phy88q1110_set_sleep(dev)

首先进行幂等检查，防止重复休眠。

接着进入phy88q1110_set_phy_mode(dev, 0, SW_TPS_MODE)读取TPS_MODE，假如已经是SW_SLEEP_MODE就直接返回E_OK说明PHY已经睡了。否则就开始进行有关读写设置休眠。

接着进入LPSD深度休眠：

```c
val = read_phy_reg(MMD3, 0x8700);
val &= ~1;                                // 不允许 LPSD power-down（保留一种 sleep 方式）
write_phy_reg(MMD3, 0x8700, val);

val = read_phy_reg(MMD3, 0x8700);
val |= 0x1f;                              // 允许所有 5 个唤醒源
write_phy_reg(MMD3, 0x8700, val);
sleep 10ms;
```

然后确认睡眠并断电。 phy88q1110_is_sleep(phy_dev)->phy88q1110_set_power(phy_dev, 0)

最后完成一些收尾工作，一些状态位的设置以及事件上报。

### 唤醒

phy88q1110_wakeup(dev) -> phy88q1110_set_wakeup(dev)

先保持 RESET 复位状态 + 拉 WAKE_IN 高，让 PHY 感知到本地唤醒请求，然后释放 RESET，PHY 在自检过程中识别 WAKE_IN 脉冲并退出 LPSD，INH 随之翻转。接着进行上电+释放 WAKE_IN+释放 RESET 的完整动作。
